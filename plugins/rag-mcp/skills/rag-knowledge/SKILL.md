# 지식 베이스 검색 (rag-mcp)

`rag` MCP 서버는 조직의 런북, RCA(근본 원인 분석) 같은 운영 문서를 검색하는 도구를 제공합니다.
서버 운영자가 쓰기 도구를 켠 경우에만 `rag_add_document` / `rag_delete_document`로 문서를 추가·삭제할 수
있습니다(도구 목록에 없으면 꺼져 있는 것입니다).

## 언제 쓰나

- 에러나 알림을 진단하기 **시작할 때** — 추측하기 전에 같은 증상을 다룬 문서(RCA, 런북)부터 찾습니다.
- 특정 컴포넌트나 작업의 정해진 처리 절차(런북)가 필요할 때
- 사용자가 과거 사례, 원인, 조치 이력처럼 조직 내부의 운영 지식을 물을 때

일반적인 기술 지식(공식 문서에 나오는 내용)만으로 충분한 질문에는 쓰지 않아도 됩니다.

## 도구

| 도구 | 언제 쓰나 |
|------|------|
| `search_runbooks(query, cluster?, component?, limit?)` | "처리 절차가 뭐지?" — 런북만 검색 |
| `rag_search(query, doc_type?, cluster?, component?, limit?)` | 유형을 가리지 않고 검색 (`doc_type`: `runbook`, `rca`, `note` 등) |
| `rag_collections()` | 결과가 계속 비어 있을 때 — 지식 베이스가 채워졌는지 확인 |
| `rag_health()` | 도구 호출이 실패할 때 — Qdrant와 임베딩 엔드포인트 상태 확인 |
| `rag_list_documents(folder?, subdir?, limit?)` | "어떤 문서가 있지?", "검토할 초안은?" — 정식 문서(`official/`) 또는 초안(`draft/`) 파일 목록. 자세한 사용법은 `rag-list-documents` 스킬 |
| `rag_add_document(title, content, doc_type?, ...)` | (켜져 있을 때만) 사용자가 문서 추가를 요청했을 때 — 자세한 사용법은 `rag-add-document` 스킬 |
| `rag_delete_document(source)` | (켜져 있을 때만) 사용자가 초안(`draft/`) 문서 삭제를 요청했을 때 — 자세한 사용법은 `rag-delete-document` 스킬 |

`limit`의 기본값은 5, 최대 20입니다.

## 진단할 때의 순서

1. **같은 증상 검색** — `rag_search`로 같은 증상을 다룬 문서를 찾습니다(과거 원인 분석만 보려면 `doc_type="rca"`).
   클러스터를 알면 `cluster`를 넘기세요.
2. **절차 검색** — 관련 컴포넌트의 런북을 `search_runbooks`로 찾습니다. 컴포넌트를 알면 `component`를
   넘기세요.
3. **근거와 함께 답변** — 찾은 문서의 원인과 조치를 현재 상황과 비교해 설명하고, 출처를 밝힙니다.
4. **찾지 못했다면** 그 사실을 분명히 말하고, 일반 지식에 기반한 판단임을 구분해서 답합니다.

## 질의 작성 요령

검색은 키워드 일치가 아니라 **의미**로 이루어집니다(키워드 검색도 함께 쓰입니다).

- 증상을 **자연어 문장**으로 쓰세요.
  - 좋음: `노드 재부팅 후 Longhorn 볼륨이 attaching 상태에서 멈춤`
  - 나쁨: `longhorn 오류`
- 에러 문자열, 리소스 이름, 상태 값은 **원문 그대로** 넣으세요(`CrashLoopBackOff`,
  `FailedAttachVolume`, `Multi-Attach error` 등). 정확한 토큰은 키워드 검색으로도 찾습니다.
- 결과가 마땅치 않으면 표현을 바꿔 한두 번 더 검색해 보세요(증상 중심 ↔ 원인 중심, 한국어 ↔ 영어 용어).

## 필터

| 필터 | 종류 | 결과가 없을 때 |
|------|------|------|
| `cluster` | 소프트 | 서버가 클러스터 조건을 빼고 전체 범위로 다시 검색 |
| `component` | 하드 | 빈 결과 그대로 → 필요하면 `component` 없이 다시 검색 |
| `doc_type` | 하드 | 빈 결과 그대로 |

## 결과 해석

- **`cluster_narrowed`**
  - `true`: 지정한 클러스터에서 찾은 결과입니다.
  - `false`: 그 클러스터에는 없어서 **다른 클러스터의 선례**를 돌려준 것입니다. 답변에서 이 점을
    분명히 밝히세요.
- **`score`**: 순위를 매기는 상대적인 값입니다. 하이브리드 검색에서는 작은 수치로 나오므로, 절대적인
  유사도로 해석하지 마세요. 리랭킹이 켜져 있으면 `rerank_score`도 함께 나옵니다.
- **`truncated: true`**: 텍스트 일부만 돌려준 것입니다. 핵심 내용이 잘렸다면 더 구체적인 질의로 다시
  검색하세요.
- **출처**: 답변에 결과의 `title`과 `source`(문서 경로)를 인용해, 사용자가 원문을 확인할 수 있게 하세요.
  `source`로 문서가 정식 문서인지 초안인지 알 수 있습니다(아래 "문서 디렉터리").

## 문서 디렉터리 (정식 문서와 초안)

서버의 문서는 두 폴더로 나뉘고, 검색 결과의 `source`가 어느 폴더의 문서인지 알려 줍니다. 두 폴더 모두 검색됩니다.

| `source` | 의미 | 누가 만드나 |
|------|------|------|
| `official/...` | **정식 문서** — 사람이 관리하고 검토한 문서 | 서버 관리자 |
| `draft/...` | **초안** — 아직 사람이 검토하지 않은 문서 | 쓰기 도구를 쓴 모델 (`rag_add_document`) |

- 초안을 근거로 답할 때는 **검토 전 초안**이라는 점을 밝히세요.
- 정식 문서와 초안의 내용이 다르면 정식 문서를 우선하고, 차이가 있다는 점을 알려 주세요.
- 문서 유형(`runbook`, `rca` 등)은 폴더가 아니라 문서의 `doc_type`으로 구분합니다. 유형으로 좁히려면
  `doc_type` 필터나 `search_runbooks`를 쓰세요.
- 초안은 서버 관리자가 검토한 뒤 `rag-promote` 명령으로 `official/`에 올립니다(승격). 승격하면 `source`가
  `draft/<경로>`에서 `official/<경로>`로 바뀝니다. 승격은 모델이 할 수 없습니다.
- `draft/`로 시작하지 않는 문서(`official/...`, 그 밖의 경로)는 모두 사람이 관리하는 문서입니다.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
|------|------|
| `collection ... not found` 오류 | 지식 베이스가 아직 만들어지지 않았습니다. 서버 관리자에게 `rag-ingest` 실행을 안내하세요. |
| 결과가 항상 비어 있음 | `rag_collections()`로 포인트 수를 확인하세요. 0이면 문서가 수집되지 않은 것입니다. |
| 임베딩 관련 오류 (`EMBEDDINGS_BASE_URL is not set`, 연결 실패, HTTP 401/404 등) | `rag_health()`로 확인한 뒤, 서버의 임베딩 엔드포인트 설정 문제임을 사용자에게 알리세요. |
| 도구 자체가 보이지 않거나 연결 실패 | 서버 주소(환경 변수 `RAG_MCP_URL`이 있으면 그 값, 없으면 플러그인의 `server_url` 설정)와 rag-mcp 서버 실행 여부를 확인하도록 안내하세요 (`/plugin configure rag-mcp@rag-mcp`, `/mcp`). |

## 문서 추가·삭제 (켜져 있을 때만)

이 도구들은 **초안 폴더 `draft/`만** 다룹니다(위 "문서 디렉터리").

- 추가한 문서는 항상 `draft/<제목>.md`에 초안으로 저장되고 바로 검색됩니다. 문서 유형은 `doc_type` 인자로
  정하며 폴더에는 영향을 주지 않습니다.
- 정식 문서(`source`가 `draft/`로 시작하지 않는 문서)는 바꾸거나 지울 수 없습니다. 사용자가 정식 문서의
  수정·삭제를 요청하면 서버 관리자가 직접 해야 한다고 안내하세요. 고친 내용을 초안으로 추가해 두고 관리자가
  검토하게 할 수는 있습니다(사용자가 원할 때만).
- 초안을 정식 문서로 올리는 것(승격)은 서버 관리자가 `rag-promote <source>` 명령으로 합니다.

### 자세한 사용법

- 추가: `rag-add-document` 스킬 — 요청 확인, 중복 확인, 본문 작성 요령, 저장 전 사용자 확인, 오류 대응
- 삭제: `rag-delete-document` 스킬 — 대상 찾기(`rag_list_documents(folder="draft")`), 삭제 전 확인, 결과 해석

두 도구 모두 **사용자가 명시적으로 요청했을 때만**, **저장·삭제 전에 사용자의 확인을 받은 뒤에** 쓰세요.

## 하지 말아야 할 것

- 검색 결과에 없는 원인 분석이나 절차를 **지어내지 마세요.** 찾지 못했으면 찾지 못했다고 말하세요.
- 과거 사례의 조치를 현재 상황에 그대로 적용하라고 단정하지 마세요. 증상과 환경이 같은지 먼저 비교하세요.
- 런북의 위험한 조치(삭제, 재시작 등)는 런북에 적힌 주의 사항과 함께 전달하세요.
