# rag-mcp 지식 베이스 검색

이 플러그인은 `rag` MCP 서버의 읽기 전용 검색 도구를 제공합니다. 모델은 검색만 할 수 있고,
지식 베이스에 쓰지는 못합니다.

## 언제 쓰나

- 에러, 알림, 장애를 진단하기 시작할 때 — 같은 증상의 과거 장애와 그 근본 원인부터 찾습니다.
- 컴포넌트나 작업의 정해진 처리 절차(런북)가 필요할 때.
- 사용자가 조직 내부의 운영 지식(과거 사례, RCA, 절차)을 물을 때.

## 도구 고르기

| 상황 | 도구 |
|------|------|
| "전에 이런 일이 있었나?" | `search_incidents` |
| "처리 절차가 뭐지?" | `search_runbooks` |
| 유형을 가리지 않고 찾기 | `rag_search` |
| 결과가 계속 비어 있음 | `rag_collections`로 지식 베이스가 채워졌는지 확인 |
| 도구 호출이 실패함 | `rag_health`로 Qdrant / 임베딩 엔드포인트 상태 확인 |

## 검색 요령

- 키워드가 아니라 의미로 검색하므로, 증상을 자연어 문장으로 서술하세요. 에러 문자열이나 리소스
  이름(`CrashLoopBackOff`, `FailedAttachVolume` 등)은 그대로 넣으면 키워드 검색에도 걸립니다.
- 클러스터가 정해져 있으면 `cluster`를 넘기세요. 같은 클러스터 결과가 없으면 서버가 전체 범위로
  다시 검색하고 응답에 `cluster_narrowed: false`를 표시합니다 — 이때는 다른 클러스터의 선례라는
  점을 사용자에게 밝히세요.
- `component`는 하드 필터입니다. 결과가 비면 `component` 없이 한 번 더 검색해 보세요.
- 결과의 `source`(문서 경로)와 `title`을 답변에 인용해, 사용자가 원문을 확인할 수 있게 하세요.
- 결과가 `truncated: true`이면 일부만 반환된 것입니다. 핵심 내용이 잘렸다면 더 구체적인 질의로
  다시 검색하세요.
